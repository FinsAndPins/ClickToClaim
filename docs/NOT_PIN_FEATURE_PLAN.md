# Not Pin Feature Plan (Pricing Harness)

Last updated: 2026-05-19

This document captures the agreed design for a future "Not Pin" feature in Lexi's pricing harness. It is intentionally implementation-ready context only; no harness or builder code changes are included in this step.

## Background

- RF-DETR can mis-detect non-pin artifacts, for example:
  - a dangle boxed separately from the actual pin
  - an open-hinge pin boxed as two pins
- Current workaround is to set the non-pin item price to `$0`.
- `$0` created Whatnot CSV issues (rows can be floored to `$10` by default behavior).
- We added flag handling for explicit zero pricing (`lexi_raw_price_zero=Y`) and exclusion support, but this is still a workaround.
- A true `$0` pin and "this detection is not a pin" are different signals and should be modeled separately.

## Goal

Add a per-pin "Not Pin" toggle in the pricing harness that means:

> "This detection is not a real pin, exclude it everywhere."

## Locked Decisions (2026-05-19)

1. **Storage**
   - Store "Not Pin" state in Firebase RTDB.
   - Reuse the existing pricing collaboration Firebase project (the same one Lexi already uses).
   - Exact path and node shape are still TBD and require schema inspection first.
2. **Visual treatment**
   - Marked items should render as if RF-DETR never detected them:
     - no price overlay
     - no bounding box
     - no badge
   - The board should look identical to an undetected area.
   - Must remain reversible (see "Reversibility" decision).
3. **Whatnot CSV behavior**
   - Marked "Not Pin" items are omitted from CSV output entirely.
   - This is preferred over adding another CSV flag column.
4. **Reversibility**
   - Required.
   - Preferred interaction model: a "Show hidden / Not Pin items" toggle that reveals marked items as ghosted/striped boxes so Lexi can tap to un-mark.
5. **Aggregate totals**
   - Marked items are excluded from:
     - total pin count
     - total value shown at the top of the harness

## Open Implementation Questions

- **Exact Firebase schema**
  - Should this be a sibling field on the existing price node, or a separate tree (for example `not_pin/{stem}/{crop}: true`)?
  - Must inspect the actual pricing collab structure first.
  - Coordinate with the post-show security hardening backlog so schema work lands with tightened rules and a reliable export path for analysis.
- **Where the UI control should be added**
  - Current harness `index.html` is regenerated by `build_testing_ui.py` in:
    - `/Users/steve/Library/Mobile Documents/com~apple~CloudDocs/Cursor Projects/PinPricingStudyMVP_RFDETR_TEST/`
  - Candidate approaches:
    - **A:** modify `build_testing_ui.py` (long-term correct; broadest blast radius)
    - **B:** prototype on a sibling page (safest; does not get overwritten by regeneration)
    - **C:** post-build patch script (fragile)
  - **Planned sequence:** B first, A after proven in real show use.
- **Page topology with live CTR overlay**
  - Decide whether "Not Pin" should eventually share one advanced sibling page with CTR overlay features.
  - Current preference: keep separate during prototyping, combine once both features are stable.
- **Un-mark click target when item is invisible**
  - Likely solved by a "Show Not Pin items" toggle that temporarily reveals ghosted hidden detections for review.
- **Whatnot builder changes**
  - `build_whatnot_*.py` should read the new Not Pin flag and skip flagged rows.
  - Keep existing `$0` handling as a legacy fallback for older data.
- **Live CTR overlay interaction**
  - If a Not Pin area received clicks, still show CTR click overlay indicators for operator awareness.
  - Item remains excluded from CSV regardless of click history.
- **Migration policy**
  - Do not retro-convert historical `$0` rows.
  - Apply Not Pin behavior going forward only.

## Implementation Phases (Future)

1. Inspect pricing-collab Firebase schema and choose final Not Pin flag shape/path.
2. Build a sibling pricing page with Not Pin toggle + Firebase write flow (path-limited, no main-page edits).
3. Add "Show Not Pin items" toggle on that sibling page for reversible un-marking.
4. Update `build_whatnot_*.py` to skip rows flagged Not Pin.
5. After at least one clean show run using sibling page, fold feature into `build_testing_ui.py` so future generated harnesses include it.

## Safety Rules (Carried Forward)

- Never modify Lexi's primary `testing_ui_visual_baseline/index.html` for an in-flight show.
- Never modify `ClickToClaim/` or `ClickToRequest/` for pricing feature prototyping.
- Use path-limited commits only.
- Build on a sibling page first, validate in show conditions, then consider generator changes.
